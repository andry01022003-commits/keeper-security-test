- **The Go toolchain floor for every binary Artifact Keeper builds with Go moves to go1.27.3, and the scanner adapter is versioned to 1.6.0 to carry it** (#4852). `GO_MIN_PATCH` was 1.27.2 in the backend, the Alpine backend and the scanner adapter, and the adapter's bundled trivy was built on stdlib v1.27.2, which carries CVE-2026-111943 (HIGH). The floor is raised in all three Dockerfiles at once rather than one image at a time, because the stdlib is a property of the compiler, not of the image that happened to be reported first — the watch that found it only named the adapter. `docker/scanner-adapter/VERSION` moves 1.5.0 -> 1.6.0 because that file is a source path of a version-pinned component and 1.5.0 is already published (exact tags are never republished), so it could not be edited without a bump; the digest itself stays on `0.76.0-r1` until `artifact-keeper/trivy` publishes `0.76.0-r2`. This does **not** by itself unblock the next Docker Publish: the adapter's `trivy` stage is pinned by digest and that binary must be rebuilt and published upstream first (issue #4852, step 1 — `artifact-keeper/trivy` branch `fix/4819-go1.27.3-cve-2026-111943`, not yet opened as a PR there), then the digest repointed here in a follow-up, which is the one remaining edit.
