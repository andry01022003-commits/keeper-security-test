- **Scan-on-proxy now gates `.gem` downloads from RubyGems Remote and Virtual repositories** (#4104, part of #4097). With `scan_on_proxy` on, a proxied gem goes through the shared inline scan-and-block gate instead of streaming unscanned: a vulnerable gem is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, the verdict is reused for the same digest, and `fail_open`, `fail_closed` and `record_only` behave as they do for the other enforced formats. The gem is graded as the `{name}-{version}` its file name names, which its own gemspec must declare (the same pin hosted gems are scanned with); a gem whose gemspec names something else is withheld under `fail_closed` (423) without being scanned. A Virtual repository applies the stricter of its own and each Remote member's policy, and a member's block or fail-closed lock is final. On Remote and Virtual RubyGems repositories, a gem file name containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with `400`. Spec indexes and the JSON API are unchanged, and `GET /api/v1/formats` now reports RubyGems as `scan_on_proxy: "enforced"`.
