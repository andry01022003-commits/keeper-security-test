- **Origin policies now gate content a Remote repository serves from its proxy cache or upstream** (Closes #4506). A scan policy's `origin` predicates (`allowed_upstreams`, `denied_upstreams`, `allowed_repositories`, `denied_repositories`, `allowed_kinds`) were evaluated only against an `artifacts` row's recorded origin. Remote fetches for Generic, Maven, npm and the other proxied formats write a `proxy_cache_artifacts` row and no `artifacts` row, so an upstream deny policy did not stop those downloads, and `allowed_kinds` naming `proxy` could never be satisfied (#4161). Content a Remote serves now has the origin `{"kind": "proxy", "repository_key": <remote key>, "upstream_url": <the remote's configured upstream, normalized>}`, the same document an `artifacts` row in that Remote records, and the policies that apply to the Remote (its own and global ones) are evaluated against it before the proxy cache is read or the upstream is contacted. A refused download answers `403 Artifact download is blocked by the repository's scan policy`, as a blocked hosted download does, including for entries cached before the policy was attached, for presigned-redirect fast paths. A virtual repository does not serve the refused content from such a member either.

  **Upgrade note.** A policy whose origin predicates a Remote's content does not satisfy now blocks that Remote, metadata included. In particular a global policy with `allowed_upstreams` that does not list a Remote's upstream, or with `allowed_kinds` that does not include `proxy`, now refuses every download from that Remote. Review global origin policies before upgrading.
