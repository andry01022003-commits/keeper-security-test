- **Scan-on-proxy now gates package archives from Pub Remote and Virtual repositories** (#4107, part of #4097). With `scan_on_proxy` on, a proxied `packages/{name}/versions/{version}.tar.gz` goes through the shared inline scan-and-block gate instead of streaming unscanned: a vulnerable archive is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, the verdict is reused for the same digest, and `fail_open`, `fail_closed` and `record_only` behave as they do for the other enforced formats. The archive's root `pubspec.yaml` must declare the requested name and version (the scanner then grades that package version from it); an archive that does not is withheld under `fail_closed` (423) without being scanned. A Virtual repository applies the stricter of its own and each Remote member's policy, and a member's block or fail-closed lock is final. On Remote and Virtual Pub repositories, an archive name or version containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with `400`. The JSON API is unchanged, and `GET /api/v1/formats` now reports Pub as `scan_on_proxy: "enforced"`.
