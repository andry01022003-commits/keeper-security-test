- **A chunked upload into a Maven, Gradle, npm, PyPI or RPM repository is indexed by the format, as its own upload route indexes it** (#1846). `PUT /api/v1/uploads/{id}/complete` now dispatches on the repository format and runs that format's parsers and records: a Maven jar or POM gets its artifactId, version and POM metadata and appears in the generated `maven-metadata.xml`; an npm tarball's `package.json` becomes its packument version document; a PyPI wheel or sdist is validated against its `METADATA`/`PKG-INFO` and listed in `/simple/<project>/`; an RPM is named and catalogued by its NEVRA. Before, those artifacts were committed as generic rows named after the file, so the Maven, npm and PyPI indexes did not list them. A package whose embedded metadata names another package or version than its path is refused with 400, as the native route refuses it. Incus and Debian already had this since 1.11.0. Existing artifacts keep their storage keys and stay readable; they are not re-indexed. A completion that sends `Prefer: respond-async` gets 202 with the session as the poll location, for packages whose parse outlasts a proxy timeout. Chunked uploads now also get the repository's upload quarantine hold, as the native routes do, and the storage quota applies to them unless the session is a trusted replication session (an administrator or service account). See `docs/chunked-uploads.md`.
