- **A `clean` proxy verdict that graded no components is no longer reused under `fail_closed`** (#3396). Proxy scan verdicts are stored per content digest and shared by every repository that serves those bytes. A `clean` verdict with no findings and no cataloged components (for example one written by an on-demand rescan in a repository of another format) says only that the scan saw nothing it could grade, so a `fail_closed` download no longer serves from it: the bytes are scanned again as for a first pull, and a download whose identity cannot be established stays withheld (423). A conda download still reuses such a verdict when a conda repository recorded it, so a conda package with no Python or recognised binary content (such as `tzdata`) is scanned on its first `fail_closed` pull only; other bytes whose own grade catalogs nothing are scanned on each `fail_closed` pull. A rescan in a conda repository of a cached object that is not the package its file name declares follows the same catalog rule as below. A `POST /api/v1/repositories/{key}/security/proxy-scans/rescan` in a repository whose format does not scan on proxy (for example `generic`) in which the scanner catalogs nothing and finds nothing is now inconclusive: it answers 503 `RESCAN_SCAN_FAILED` and records no verdict, instead of recording `clean`.
