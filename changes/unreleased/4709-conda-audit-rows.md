- **Conda publishes, withdrawals, attestation verifications and refusals, and environment registrations and deletions are recorded in the audit log** (#4709). The native conda publish inserted its artifact row itself rather than through the audited upload service, so the audit log showed who downloaded a package but not who published it, and withdrawals, CEP-27 attestation outcomes and stored-environment changes left no row at all. A native publish (hosted or staging, every upload route) now writes `ARTIFACT_UPLOADED` with the usual artifact fields plus the conda coordinates (`name`, `version`, `build`, `subdir`, `filename`) under `details.package`; a withdrawal writes `CONDA_PACKAGE_WITHDRAWN` with the reason, the permanent hold and the CEP-6 notice id and message; an attestation PUT writes `ATTESTATION_VERIFIED` (method, identity, issuer, key fingerprint) or `ATTESTATION_REJECTED` (the failure reason the API returns, and whether the operator opt-out stored it anyway); and stored environments write `ENVIRONMENT_REGISTERED` (lockfile format, package count, scopes, whether it replaced an existing one) and `ENVIRONMENT_DELETED`. Every row names the acting user and the repository. The fields of each are listed in `docs/audit-events.md`.
