- **A virtual repository member whose upstream is down no longer stalls every metadata miss until the reverse proxy gives up** (closes #4508). When one Remote member of a virtual stopped answering (connections blackholed rather than refused), every metadata lookup that reached it waited for the upstream client's 60 second connect or read timeout, longer than a typical reverse proxy allows a request, so clients saw `504 Gateway Timeout` and builds slowed to a crawl (reported on Maven `maven-metadata.xml`). Each Remote member's metadata fetch is now bounded by a member deadline, `AK_VIRTUAL_MEMBER_METADATA_TIMEOUT_SECS` (default 20): a member that misses it fails the request promptly with a 502 that names the member, consistent with the loud member-failure policy (#4192), instead of being waited on or silently skipped. It applies to the Maven virtual `maven-metadata.xml` merges (release, plugin-prefix and SNAPSHOT) and `.meta/prefixes.txt`, to the shared first-hit metadata walk, and to the merged indexes of Helm, CRAN, Hex and Bazel virtuals, where a late member counts as a failed member (`reason="timeout"`) and is reported in `X-AK-Partial-Members` when the virtual allows partial merges. New metric: `ak_virtual_member_metadata_timeouts_total{member}`. Artifact downloads are not bounded by it.
