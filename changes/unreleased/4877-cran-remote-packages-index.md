- **A CRAN repository of type `remote` now proxies the upstream `PACKAGES`/`PACKAGES.gz` index, so R clients pointed directly at it can discover and install packages** (#4877). The source index was built from locally-catalogued rows alone, and a proxy repository only ever has rows for packages already fetched through it, so `GET /cran/{repo}/src/contrib/PACKAGES` answered an empty `200` even though the upstream (e.g. `https://cran.uib.no/`) publishes a full index; only individual package downloads were proxied, so `install.packages()` had nothing to resolve against. A remote repository now fetches the upstream `src/contrib/PACKAGES` (falling back to `PACKAGES.gz` for mirrors that ship only the gzipped form) and merges it over the locally-held rows, preserving every upstream DCF field — `Depends`, `Imports`, `LinkingTo` and the rest — because R resolves the dependency graph out of those. A locally-held package still wins its `(Package, Version)` slot, since its row carries the coordinates the download route serves from storage. An upstream that publishes no index (`404`) is not an error, but a genuine upstream failure with nothing held locally is now surfaced instead of being masked as an empty `200`.
