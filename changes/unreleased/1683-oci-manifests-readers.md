- **OCI manifest reads by digest, the referrers API and storage GC now key on the `oci_manifests` existence table** (#1683). On a hosted repository, `GET`, `HEAD` and `DELETE /v2/<name>/manifests/<digest>` resolve through the repository's record of the manifest instead of inferring it from tags and edge rows, and the #1681 content-addressable fallback is gone. The untagged child of a tagged index keeps pulling by digest after its own tag is deleted. The referrers API lists a referrer while the repository records the referrer itself, whether or not its subject exists. Deleting the last tag of an index that a tagged index of indexes still references no longer drops that index's own child edges, which stranded the grandchildren while the top index still served them. Storage GC keeps a manifest object, and the blob refs of an index's child, while the manifest is recorded, so the child of an untagged index that still pulls by digest is no longer reclaimed. Upgrading from 1.11: a rolling upgrade is supported; while 1.11 replicas still run, keep `BLOB_GC_ENABLED` unset and `GC_TRASH_RETENTION_DAYS` above the rollout length on them, as `docs/operations/oci-manifests-reconcile.md` explains with a table of what a mixed 1.11/1.12 fleet answers.
