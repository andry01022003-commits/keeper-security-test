- **The generic artifact PUT honours `If-Match` and `If-None-Match`, so a shared index document can be updated with compare-and-swap** (#4186). `PUT /api/v1/repositories/{key}/artifacts/{path}` (and the multipart upload routes) now evaluate RFC 9110 preconditions against the live artifact's ETag, which is its quoted SHA-256: `If-Match: "<sha256>"` writes only when the stored artifact is that one and then replaces it, even on a repository without versioning; `If-None-Match: *` creates only when the path is free. A failed precondition is `412 PRECONDITION_FAILED`, checked before the body is read and again with the row locked when the upload commits, so of several conditional uploads racing on one ETag exactly one succeeds and the rest get 412 (the single-winner contract unconditional uploads got in #4832). The upload's `201` and the generic download now carry `ETag`. Unconditional uploads are unchanged, a released coordinate (a versioned path) still cannot change bytes, and a malformed precondition header is a 400. The object a conditional replace leaves without a row is handed to storage GC. See `docs/generic-conditional-writes.md`.
