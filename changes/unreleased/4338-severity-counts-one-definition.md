- **Severity counts agree across the Overview dashboard, the security dashboard, the per-repository scores and the artifact view** (#4338). The same data gave three different critical counts: the security tiles and repository scores counted finding rows, so one CVE found in two packages, or by two scanners, counted twice; the repository scores were only recomputed after a scan, so acknowledging a finding changed the tiles but not the repository row; and the Overview summary counted every CVE ever recorded, including ones a rescan no longer reports, with acknowledged ones in its severity buckets. All of them now use one definition (`services/open_findings.rs`): for each artifact the latest completed scan of each scan type, one vulnerability per (artifact, advisory) where the advisory is the CVE id or the finding title, at its highest reported severity, with open vulnerabilities in the severity counts and acknowledged ones counted separately. Acknowledging or un-acknowledging a finding recomputes its repository's score, and an artifact's CVE history marks a CVE its latest scans no longer report as `fixed`. Repository scores and grades can change on upgrade because duplicates no longer count; `total_findings` on a repository score is now its open vulnerabilities, as on the dashboard. Closes #4338.
