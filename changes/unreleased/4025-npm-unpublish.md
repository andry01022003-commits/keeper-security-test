- **`npm unpublish` removes the version or package from hosted npm repositories instead of silently doing nothing** (#4025). The npm client unpublishes through `PUT /{pkg}/-rev/{rev}` (the packument without the version), `DELETE /{pkg}/-/{tarball}/-rev/{rev}` and `DELETE /{pkg}/-rev/{rev}` (the whole package), none of which were routed; the client reads the resulting 404 as "already gone", so `npm unpublish` exited 0 while the version stayed installable. These routes now exist for unscoped and scoped (`@scope/name` and `@scope%2fname`) packages. Removing a version soft-deletes its artifact through the regular artifact delete (audit entry, `artifact.deleted` webhook, replication delete tasks), drops any dist-tag that pointed at it and recomputes `latest` from the remaining versions; unpublishing the whole package removes every version and its dist-tags, after which the packument is 404. The caller needs the `delete:artifacts` token scope and the repository `delete` action (repository owners and admins; the `developer` role cannot unpublish), and `promotion_only` repositories refuse it for non-approvers, the same gates as the REST artifact delete. Remote repositories answer 405 and virtual repositories 400. This registry keeps no packument revisions, so any `{rev}` the client sends (npm sends `undefined`, since no `_rev` is served) is accepted. A `PUT /{pkg}/-rev/{rev}` that removes no version is refused with 400 rather than reported as applied, so other packument edits sent there (such as `npm owner`) fail visibly.
