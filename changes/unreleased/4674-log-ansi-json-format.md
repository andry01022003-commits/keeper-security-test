- **The backend no longer writes ANSI colour codes into collected logs, and `LOG_FORMAT=json` gains top-level request fields** (#4674). Colour escapes sat between each `key=` and its value, so Loki and SIEM string filters on `uri=`, `status=` or `correlation_id=` silently never matched. The new `LOG_ANSI` setting (`auto`, `true`, `false`) defaults to `auto`: colour only when stdout is a terminal and `NO_COLOR` is unset, so container and systemd logs are plain with no configuration; `LOG_ANSI=true` restores the previous coloured output (the formatter is unchanged). The JSON format gains top-level request fields; existing keys are unchanged: every line logged during a request now also carries `method`, `uri`, `correlation_id` and `http.route` at the top level, and the per-request `Request completed` line adds `status` (an integer), `user` (omitted when anonymous), `ip` and `latency_ms`, so detection rules can match them without descending into `fields` or `span`. The `Request completed` line in both formats now also records `user`, `ip` and `latency_ms`. `LOG_FORMAT` accepts `text` as the name of the default format (`pretty` still works). The field reference for writing detection rules is `docs/operations/logging.md`.
