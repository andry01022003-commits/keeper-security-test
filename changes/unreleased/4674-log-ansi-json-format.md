- **The backend no longer writes ANSI colour codes into collected logs, and `LOG_FORMAT=json` now puts the request fields at the top level** (#4674). Colour escapes sat between each `key=` and its value, so Loki and SIEM string filters on `uri=`, `status=` or `correlation_id=` silently never matched. The new `LOG_ANSI` setting (`auto`, `true`, `false`) defaults to `auto`: colour only when stdout is a terminal and `NO_COLOR` is unset, so container and systemd logs are plain with no configuration; `LOG_ANSI=true` restores the previous coloured output (the formatter is unchanged). `LOG_FORMAT` now also accepts `text` (the new name of the default, `pretty` still works), and its `json` format is flattened: `message` and every event field are top-level keys, the `http_request` span's `method`, `uri`, `correlation_id` and `http.route` appear on every line logged during a request, and the per-request `Request completed` line, in both formats, now carries `user` (omitted when anonymous), `ip` and `latency_ms`, with `status` as an integer in JSON. A parser of the 1.10 JSON layout that read `fields.message` or `span.correlation_id` must switch to the top-level keys. The field reference for writing detection rules is `docs/operations/logging.md`.
