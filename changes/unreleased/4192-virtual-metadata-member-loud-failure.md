- **Helm, CRAN, Hex and Bazel virtual repositories no longer serve a merged index that silently lacks a member whose metadata failed** (closes #4192). The shared member merge (`collect_virtual_metadata`) logged a member it could not fetch or parse at `warn` and merged the rest, so a client got a 200 index missing that member's packages, and concluded they do not exist or resolved a name present in two members to the lower-priority one. Conda's virtual merge already failed loudly (#4603, #4611, #4614); the shared merge behind Helm `index.yaml`, CRAN `PACKAGES` / `PACKAGES.gz`, Hex `/names` and `/versions` and Bazel module metadata now follows the same policy: by default any member that fails to fetch or whose document does not parse fails the request with 502 naming the member and the cause. A virtual with `virtual_metadata_partial` set (the same repository setting conda honours) instead gets the merge of the members that succeeded, with `X-AK-Partial-Members` naming the missing ones, `Cache-Control: no-store` and `Warning: 199`. Each failure counts in `ak_virtual_member_metadata_failures_total{format,virtual_repo,member,reason}` in both modes. A member that answers 404 publishes no such document and is not a failure, and members the caller may not read are still left out without being reported. Note for Hex: a virtual whose Remote member is `repo.hex.pm` (which serves signed protobuf rather than the JSON these endpoints merge) now answers 502 on `/names` and `/versions` unless partial merges are enabled.
