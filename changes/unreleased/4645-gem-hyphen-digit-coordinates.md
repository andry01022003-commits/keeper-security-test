- **RubyGems spec indices advertise gems whose name contains a hyphen-digit segment under the right name and version** (#4645). A gem such as `qa-gem-2` 1.0.0 pushed successfully, but `specs.4.8.gz` and `latest_specs.4.8.gz` re-split its stored filename `qa-gem-2-1.0.0.gem` at the first hyphen-digit boundary and listed it as `qa-gem` version `2-1.0.0`, so `gem install qa-gem-2` could not find it. The indices now use the name and version recorded from the gem's own gemspec whenever the stored filename agrees with them, and the filename fallback (bare-path uploads, the virtual-repo shadowing guard, generic-upload path parsing) splits at the last hyphen followed by a digit-leading version segment, without mistaking a platform's OS version (`x86_64-darwin-19`) for the gem version: `qa-gem-2-1.0.0.gem` is `qa-gem-2` / `1.0.0` and `rails-7.1.0.beta1.gem` is `rails` / `7.1.0.beta1`. Gems pushed through the native push endpoint already stored the correct coordinates and are listed correctly from this release on with no action needed. Nothing rewrites stored rows: a gem uploaded through the generic upload path with coordinates derived from a wrong filename split keeps them until it is re-uploaded.
