- **Debian remote and virtual repositories mirror flat APT repositories (`deb <uri> /`), such as Kubernetes' pkgs.k8s.io** (#4619). A remote only spoke the `dists/<suite>` layout, so the Kubernetes and openSUSE Build Service repositories could not be proxied: `GET /debian/<repo>/InRelease` was a 404 and `dists/stable/InRelease` a 502. The flat layout is now served from the repository root (and from an exact-path suite directory): `InRelease`, `Release` and `Release.gpg` pass through byte-for-byte so apt keeps verifying the publisher's key, they revalidate on the dists TTL and drive the release epoch that invalidates the indices next to them, each `Packages`/`Sources`/`Translation` index is checked against the signed `Release` before it is served, and a package is cached only when it matches the SHA-256 its cached `Packages` records; flat-layout packages are cached as immutable. Only paths an APT flat repository contains are proxied. Point apt at `deb [signed-by=<publisher key>] <base>/debian/<repo>/ /`. Setting `debian.flat_repository = true` declares a remote flat and answers its `dists/` routes with 404 and that sources line; left unset, both layouts are served and a `dists/` request that fails against an upstream which serves a flat repository answers the same way. Each decision is logged once per repository. Closes #4619.
